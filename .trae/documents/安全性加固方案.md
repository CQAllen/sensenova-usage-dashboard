# SenseNova 用量查询工具 — 安全性加固方案

> **文档状态（2026-10 更新）**：本文档是当时的加固规划，**P0 / P1 已全部实施**，P2 已逐项处理（做了 / 有理由不做，见「P2 逐项结论」）。
> 「实现步骤」保留作为变更依据的历史记录，其中个别描述与最终实现有差异，差异处已在文末「与原方案的差异」中列出。
> 当前实际的加固面以 **README 的「安全设计」章节**为准。自动化验证见 `tests/smoke_test.py`。

## 背景（Context）

本仓库是 `https://github.com/shaobingtongzhi/sensenova-usage-dashboard` 的 fork。该工具是一个本地桌面应用
（Python + pywebview + 内置 HTTP 服务 + 内嵌 HTML/JS），用于查询商汤日日新多账号的额度用量。

加固前存在若干**可被实际利用**的安全缺陷，最严重的是：本地 HTTP 服务（`127.0.0.1:5199`）**无任何鉴权与来源校验**，
而 `GET /api/accounts` 会**明文返回全部账号的用户名、密码与 JWT**；同时凭据以**明文**落盘在 `accounts.json`。

目标：在不破坏现有体验（开箱即用、自动重登、跨平台打包）的前提下，消除凭据泄漏路径、收紧本地服务暴露面、
实现凭据静态加密，并收敛其余次要问题。

## 威胁模型与边界（重要）

- **要防**：浏览器 Web 来源（DNS rebinding / CSRF / 恶意网页）、凭据文件被拷贝或误提交、云同步盘外泄、路径穿越与注入、异常信息泄漏。
- **不防（能力边界）**：同一登录用户下的本机恶意进程——它可直接读文件、读内存、直接 `curl` 本地服务。
  **因此"鉴权 token"只挡浏览器来源，真正缩小爆炸半径的是"服务端不再回传凭据"。加密只防"文件被拿走"，对同用户进程无效。**
  文档与 README 不得宣称"已彻底安全"。
- **限流的角色**：会话令牌挡不住本机循环脚本，因此限流是「避免把上游接口打爆」的兜底，不是安全边界。
  这一点决定了**每一处能触发登录的路径都必须被限住**（含自动重登与按需取明文的链路），见步骤 1 第 9 点。

## 加固范围（含实施状态）

| 优先级 | 内容 | 状态 |
|---|---|---|
| **P0（最小可用加固集）** | 本地 API 鉴权 + Host/Origin/Sec-Fetch-Site 校验；不再回传凭据；精确路径匹配 + body 上限 + 安全响应头；端口随机 + 启动失败可见；并发锁 + 原子写；错误信息脱敏；前端全量转义；`.gitignore` 补漏；配置目录迁出同步盘 | ✅ 全部完成 |
| **P1（建议）** | 凭据加密（Windows DPAPI / POSIX 0600 密钥文件）+ 旧明文自动迁移；`auth_login` 跳转域名白名单、`trust_env=False`、调试日志默认关闭并脱敏；`启动.bat` 去硬编码；`requirements.txt` | ✅ 全部完成（`trust_env=False` 实际覆盖了 4 处，超出本项范围） |
| **P2（可选）** | CSP nonce 化；`/api/usage` 频控；JWT 不落盘；`upx=False` + 签名策略；用 pywebview `js_api` 桥替代 `/api/*` | ⚠️ 部分完成，逐项结论见下节 |

### P2 逐项结论

| 项 | 结论 |
|---|---|
| `/api/usage` 频控 | ✅ 做了。最终有 4 个 `_Throttle`（usage / keys / login 按账号 / 出图按账号），外加 `auth_login` 内的登录闸门 |
| `upx=False` | ✅ 做了（`.spec` 两处）。收益：UPX 压缩是 Windows AV 误报的主要诱因之一 |
| 签名策略 | ❌ 做不了。Authenticode / macOS 公证都需要外部账号与证书，不属于代码改动 |
| CSP nonce 化 | ❌ 有意不做。最终实现比原要求更严：脚本一律走外部 `app.js`（`script-src 'self'`，零内联脚本），nonce 化只剩 `style-src`，改动面大而收益接近零 |
| JWT 不落盘 | ❌ 有意不做。`jwt_token` 与 `password` 在**同一个加密信封**内，加密只防"文件被拷走"；能解开的攻击者已持有密码、可自行登录，删掉 JWT 不减少任何暴露面，反而让每次刷新多一次登录请求 |
| js_api 替代 HTTP | ⚠️ 部分。图像下载走 `ImageApi.save_image` 桥（原生保存对话框最可靠），HTTP 面保留但已收得很紧（令牌 + 来源校验 + CSP + 频控 + 不回传凭据） |

## 实现步骤（按依赖顺序，历史记录）

### 步骤 1 — 收紧本地服务与凭据暴露（`dashboard.py`）【P0，其余步骤的前置】

1. **启动常量化**：`SERVER_PORT = 0`（临时端口）；新增 `MAX_BODY_BYTES = 64*1024`、`threading.Event` 就绪/错误信号、
   `AUTH_TOKEN = secrets.token_urlsafe(32)`（**进程启动生成一次、永不轮换**，避免页面重载竞态）。
2. **统一请求校验** `_check_request()`，在 `do_GET`/`do_POST` 首行调用：
   - `Host` 头必须是 `127.0.0.1:<port>` / `localhost:<port>`（含无端口写法），否则 403 —— **必须同时覆盖 `/`**（防 DNS rebinding 的关键）；
   - `Origin` 只要存在就必须同源，否则 403；`Sec-Fetch-Site: cross-site` 直接 403；
   - 仅对 `/api/*` 校验 `X-Auth-Token`（`hmac.compare_digest`），不接受 query 传参（防 Referer 泄漏）。
3. **统一响应** `_send_json(code, obj)`：统一 `Content-Type` + 安全响应头
   （`Content-Security-Policy`、`X-Content-Type-Options: nosniff`、`Cache-Control: no-store`、`Referrer-Policy: no-referrer`）；
   覆盖 `send_error` 使 403/404 也带安全头；固定 `server_version` 不吐 Python 版本。
4. **路径精确匹配**：用 `urllib.parse.urlsplit(self.path).path` 精确比对，替换 `startswith` 匹配。
   POST 先校验 `Content-Length` 为正且 ≤ body 上限；超限回包前**有界排空请求体**（否则 socket 残留数据会以 RST 关闭连接，客户端收不到 413）。
5. **不再回传凭据**：
   - `GET /api/accounts` → 只返回 `{username, has_password, has_token}`，**删除 password / jwt_token 字段**；
   - `POST /api/login` 响应去掉 `"token": token`（token 仅服务端经 `update_account` 保存）；
   - `POST /api/accounts` 按 username **合并**：密码为空=保留旧值（`password_clear:true` 才清空）；payload 中不存在的账号=删除；`jwt_token` 只写不读。
6. **前端适配**：令牌用 `.replace()` 注入（绝不用 `str.format`）；`apiFetch()` 自动带 `X-Auth-Token`；
   密码框恒为空、`placeholder` 提示沿用已存值；`escHtml` 先 `String(s)` 再转义；补齐所有未转义字段。
7. **端口与启动健壮性**：`start_server` 捕获绑定异常并置错误信号；`main` 用 `event.wait(10)`，
   失败时展示可读错误页，**移除 `while _server_port is None` 死循环挂起**。
8. **首次运行不落盘空模板**：改为内存空行，用户保存时才写文件。
9. **限流**（规划时为 P2，最终归入 P0 兜底）：`_Throttle` 按 key 最小间隔 + `threading.Lock` + key 上限防字典膨胀；
   `/api/usage`、`/api/keys` 全局，`/api/login`、出图按账号；超限 429 + `Retry-After`。**校验必须在限流之前**，否则一个坏请求就吞掉额度。

### 步骤 2 — 凭据静态加密与落点治理（新增 `credstore.py` + `dashboard.py`）【P1】

1. **配置目录迁移**：`resolve_config_dir()`——Windows 用 `%LOCALAPPDATA%\SenseNova用量查询`，
   macOS 用 `~/Library/Application Support/...`，Linux 用 `~/.config/...`；源码态默认脚本目录，命中
   OneDrive/Dropbox/坚果云等同步盘时自动改用用户级目录。**冻结态不写 `.app/Contents/MacOS`**（否则破坏签名）。
2. **`credstore.py`**：信封格式 `{"v":1,"scheme":"dpapi|keyfile|plain","data":"..."}`，自描述便于将来换算法。
   - 密钥：Windows 用 DPAPI（`ctypes` 调 `crypt32`，系统 DLL，PyInstaller 下可用）；POSIX 用 0600 权限密钥文件。
   - 加解密：`cryptography.fernet.Fernet`。
   - 读写：`tempfile` 同目录 + `os.replace` **原子写**，POSIX `chmod 0600`。
   - **缺失加密组件时降级为明文 + 告警**，但 `启动.bat` 必须把 `cryptography` 纳入自检，否则这个降级是无声的。
3. **收敛并发**：`_mutate_doc(fn)` 内加模块级 `threading.Lock()`，消除并发读改写竞态。
   用量查询的写盘包 try/except（**失败不影响本次结果**）；**配置保存的写盘失败必须向上抛**——吞掉等于界面谎报「已保存」。
4. **迁移与容错**：旧明文 → 读取即加密覆盖；解密失败 → 重命名 `.bad` 并告警，**保证不崩**。
   明确告知用户旧明文可能残留在同步盘 / 备份 / git 历史。
5. **`.gitignore` 补漏**：`*.key`、`accounts.json`、`auth_login_last_error.log`、`*.bad`。

### 步骤 3 — 收口登录模块（`auth_login.py`）【P1】

1. `_write_debug_log`：落点改到配置目录，默认**关闭**（`SENSENOVA_AUTH_DEBUG=1` 才写），
   遮蔽 `code=`/`login_challenge=`/`access_token`/`Bearer `/JWT 形状串，响应片段截断到 500。
2. `_follow_until`：URL 白名单（仅 `https` 且 `*.sensenova.cn` / `*.sensecore.cn` / `*.sensecoreapi.cn`）；`stream=True` + 限读 64KB。
3. **`trust_env = False`**：不仅 `auth_login`，出网请求一律禁用环境代理。JWKS 端点虽不带凭据，
   但返回的公钥决定密码加密给谁——公钥被中间人替换等于密码直接外泄。最终覆盖 4 处：
   `auth_login`（登录链路 + JWKS）、`sensenova_api`（用量 / Key）、`imagegen`（出图 + 回退下载）。
4. 异常文案去绝对路径；`dashboard.py` 中 `str(e)` 统一过 `sanitize_error()`。
5. **登录闸门**（后续补充）：`login()` / `refresh()` 内按凭据最小间隔 3 秒。
   放在重试循环**之外**——内部网络重试是同一请求的自愈，不该各自消耗额度。
   放在这里而非路由层，是因为自动重登、`/api/apikey`、出图路由都走同一条链，且那些路由本身没有 HTTP 限流。

### 步骤 4 — 脚本 / 打包 / 文档【P1】

1. `启动.bat`：删除硬编码解释器路径，改为 `.venv` → 系统 Python 探测 → 自动建环境；两处依赖自检含 `cryptography`。
2. `build_mac.sh`：删除写配置模板的 heredoc（改由应用首次运行生成）；framework Python 探测（`PYTHONFRAMEWORK`）；ad-hoc 签名。
3. 新增 `requirements.txt`，更新 README。
4. 版本号三处统一（`dashboard.APP_VERSION` / `version_info.txt` / `build_mac.sh`）。

## 兼容性与回归风险（当时评估）

- **自动重登**：`ensure_token` 逻辑不动，仅保证写盘失败不干扰查询结果。
- **密码框不回显**：用 `placeholder` + 已保存角标缓解。
- **改用户名 = 删旧建新**：会静默丢失旧密码 → 已加二次确认。
- **手动粘贴 JWT**：因「不回传凭据」而失效，JWT 改为只写不读。
- **空行保存会清空全部账号**：已加二次确认。
- **macOS 打包**：配置目录迁出 bundle，顺带修复「写入 bundle 破坏签名」。

## 与原方案的差异（后续补充的改动）

实施后又发现的问题，都不在原方案范围内：

**服务端**
- 413 未排空请求体 → Windows 上连接被强制中断，客户端收不到 413（测试抓到的产品 bug）
- `GET /api/accounts`、`GET /api/settings` 缺 try/except → 异常直接断连，前端表现为白屏而非报错
- `_mutate_doc` 吞掉写盘失败 → 界面谎报「已保存」
- 频控缺失（含自动重登链路的登录闸门）
- 图像 URL 回退下载无域名白名单（SSRF）、格式无白名单（头注入）、无限流读
- 图像缓存只有条数上限，无总字节上限（4K 图单张 30MB+，长期挂机可常驻上 GB）
- API Key 列表每次调用都重新拉取 → 加了 TTL 缓存与主动刷新联动
- `_collect_accounts` 并发下的 token 写回竞态（按 username 收敛到 `_accounts_lock`）

**前端**
- 非 200 响应体被当成空数据渲染（429 显示为「还没有配置任何账号」）
- `tick()` 慢查询期间 countdown 持续为负，每秒重复发请求
- `_igImage.b64` 只写不读，约 1GB 冗余内存
- 会话令牌曾出现在下载 URL 中（浏览器历史 / Referer）
- 改用户名静默丢密码、重复用户名不查重、`resp.ok` 检查不统一
- 参考图无体积校验 → 撞 32MB body 上限只回「请求体过大」；现改为解码后按需缩放到 2048 转 JPEG

**打包 / 脚本**
- `upx=True` → `upx=False`；版本号三处不一致；`启动.bat` 依赖自检漏检 `cryptography`
