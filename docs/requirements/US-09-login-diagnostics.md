# US-09 登录诊断中心

| 项目 | 内容 |
|---|---|
| Story ID | US-09 |
| 优先级 | P1 |
| 依赖 | 无（复用现有登录流程与调试日志能力） |

---

## 1. 背景与问题

账号登录依赖 SenseNova 平台的 OAuth 与密码加密流程。平台一旦调整接口、加密参数或网关策略，应用会出现「查询异常」，但界面只显示一句脱敏错误。普通用户无法判断是网络问题、密码错误、平台改版，还是账号权限不足；开发者也只能依赖环境变量开启调试日志，在本地翻文件。

本 Story 把登录链路拆成可观察的步骤，在应用内给出结论与下一步动作，并为反馈问题提供可脱敏导出的诊断记录。

---

## 2. 用户故事

> 作为账号突然查询失败的用户，我希望在工具里直接看到登录流程卡在哪一步、可能的原因是什么，并能导出一份脱敏记录发给开发者，这样不必自己猜测或反复重试。

**完成条件**：用户选择账号执行诊断后，能看到每一步的成功 / 失败 / 跳过状态与原因，并能在不泄露凭据的前提下导出记录。

---

## 3. 范围

### P0

- 设置页新增「登录诊断」入口。
- 选择账号后执行诊断，展示步骤化结果。
- 每步显示状态、耗时、脱敏错误摘要与建议。
- 一键导出脱敏诊断记录（文本）。
- 诊断频控，避免触发平台风控。
- 不修改账号配置、不保存诊断中获得的新凭据。

### P1

- 诊断结果一键复制。
- 对比两次诊断结果，定位平台变化。
- 模拟完整密码登录（默认关闭，需显式勾选并提示风险）。
- 平台接口健康状态汇总（所有账号批量诊断）。

### 不做

- 自动修复账号配置。
- 抓包或展示完整请求 / 响应体。
- 上传诊断记录到服务器。
- 绕过平台验证码或风控。

---

## 4. 核心流程

```
设置页 → 登录诊断
  → 选择账号
  → 点击「开始诊断」
  → 按步骤执行：
      1 本地配置检查
      2 网络连通性
      3 鉴权服务可用性
      4 令牌获取（优先 refresh_token）
      5 令牌有效性
      6 用量接口权限
      7 Key 列表权限（可选）
  → 任一步失败：标记失败，跳过依赖步骤，继续可独立执行的步骤
  → 展示汇总与建议
  → 用户可导出脱敏记录
```

## 5. 功能需求

### US09-FR1 诊断入口与账号选择

**规则**：

1. 入口位于「系统设置」页，名称「登录诊断」。
2. 进入后展示账号下拉，默认选中最近一次查询异常的账号；无异常账号时选中第一个账号。
3. 无账号时展示空态与「去添加账号」。
4. 诊断页不展示账号密码、JWT、API Key。
5. 同一账号同一时间只允许一个诊断任务。

### US09-FR2 诊断步骤定义

| 序号 | 步骤 | 成功判据 | 失败时是否阻断后续 |
|---|---|---|---|
| 1 | 本地配置检查 | 账号存在，且具备密码或 refresh_token | 阻断 |
| 2 | 网络连通性 | 能访问平台鉴权域名（超时 5 秒 `[Assumption, TBD]`） | 阻断鉴权相关步骤，可继续本地检查 |
| 3 | 鉴权服务可用性 | 鉴权端点返回预期响应（非 5xx / 非证书错误） | 阻断 4–7 |
| 4 | 令牌获取 | refresh_token 换取成功，或已持有有效 JWT | 阻断 5–7 |
| 5 | 令牌有效性 | JWT 可解析，`exp` 未过期，账号标识存在 | 阻断 6–7 |
| 6 | 用量接口权限 | 用量查询返回 2xx 且结构可解析 | 阻断 7 |
| 7 | Key 列表权限（可选） | Key 列表返回 2xx 或明确无权限 | 不阻断 |

**规则**：

1. 步骤 4 优先使用 refresh_token；refresh_token 不可用时，若用户开启「包含密码登录测试」，才执行密码登录。
2. 默认不执行密码登录测试，避免消耗登录尝试次数与触发风控。
3. 密码登录测试开启时，页面明确提示「将真实尝试登录，可能更新平台会话」。
4. 诊断过程不写回账号配置；即使获取到新令牌，也只在诊断任务内使用，诊断结束即丢弃。
5. 单个步骤超时 15 秒 `[Assumption, TBD]`，整体诊断超时 60 秒。

### US09-FR3 步骤结果展示

**字段**：

| 字段 | 说明 |
|---|---|
| 步骤名称 | 见 US09-FR2 |
| 状态 | 成功 / 失败 / 跳过 / 进行中 |
| 耗时 | 毫秒或秒，保留一位小数 |
| 摘要 | 成功时一句话结论；失败时为脱敏错误码与原因 |
| 建议 | 可执行的下一步，例如「检查网络代理」「重新登录」「平台接口可能已变更」 |

**规则**：

1. 步骤按顺序展示，进行中的步骤有加载态。
2. 失败步骤展开显示错误摘要；成功步骤默认收起。
3. 跳过步骤注明原因，如「前置步骤失败」。
4. 汇总区给出整体结论：
   - 全部成功：「登录链路正常，问题可能出在用量接口或平台限流。」
   - 关键步骤失败：「登录失败，原因：{摘要}」
   - 部分成功：「登录正常，但 {步骤} 失败。」
5. 错误信息必须脱敏，不得包含密码、JWT、完整 Key、完整请求 URL 中的 token 参数。

### US09-FR4 诊断记录导出

**规则**：

1. 导出格式为纯文本（`.txt`），内容包含：诊断时间、应用版本、操作系统、账号名、各步骤状态与耗时、脱敏错误摘要、建议。
2. 不包含：密码、JWT、refresh_token、API Key、Cookie、完整请求头、请求体。
3. 账号名可按用户选择脱敏为 `account_1` 形式；默认保留原名 `[Assumption, TBD]`。
4. 使用原生保存对话框，默认文件名 `SenseNova诊断_{YYYYMMDD_HHMM}.txt`。
5. 导出成功后提示路径。
6. 用户取消保存不报错。

### US09-FR5 频控与并发

**规则**：

1. 同一账号 30 秒内最多执行一次诊断 `[Assumption, TBD]`；按钮在冷却期禁用并显示倒计时。
2. 诊断进行中不允许切换账号后再次发起；可取消当前诊断。
3. 取消诊断后立即停止后续步骤，已完成步骤结果保留。
4. 批量诊断（P1）需串行执行，账号之间间隔不少于 3 秒。

### US09-FR6 取消

**规则**：

1. 用户可随时取消诊断。
2. 取消后当前在途请求尽力中断，后续步骤标记「未执行」。
3. 取消不影响账号现有状态。

## 6. 界面与交互

设置页：

```
登录诊断                                        [开始诊断]
账号 [account_03 ▾]   [ ] 包含密码登录测试（可能触发风控）

✓ 本地配置检查            12 ms   已配置密码与刷新令牌
✓ 网络连通性              183 ms  可访问鉴权服务
✓ 鉴权服务可用性          221 ms  响应正常
✗ 令牌获取                1.2 s   refresh_token 已失效（invalid_grant）
  建议：到账号管理页重新登录
- 令牌有效性              跳过    前置步骤失败
- 用量接口权限            跳过    前置步骤失败
- Key 列表权限            跳过    前置步骤失败

结论：登录失败，refresh_token 已失效。
[导出诊断记录] [复制结论]
```

- 「开始诊断」在运行中变为「取消」。
- 失败步骤使用红色状态图标，跳过使用灰色。
- 步骤区域可滚动，整体高度不超过一屏。

## 7. 数据与状态

| 对象 | 字段 | 说明 |
|---|---|---|
| 诊断任务 | 任务 ID、账号、开始时间、当前步骤、状态 | 内存态 |
| 步骤结果 | 步骤、状态、耗时、脱敏摘要、建议 | 内存态；导出时序列化 |
| 冷却记录 | 账号、上次诊断时间 | 内存态 |
| 诊断记录 | 见 US09-FR4 | 不自动持久化，仅用户导出 |

---

## 8. 异常与边界

| 场景 | 行为 |
|---|---|
| 无网络 | 网络步骤失败，后续鉴权步骤跳过 |
| 证书错误 / 代理拦截 | 归类为网络或安全错误，建议检查代理与系统时间 |
| 平台 5xx | 标记平台不可用，建议稍后重试 |
| 平台改版导致结构变化 | 标记「响应结构不符合预期」，建议升级应用 |
| refresh_token 被并发刷新 | 提示令牌已被更新，建议重新诊断；不自动重试 |
| 用户快速重复点击 | 冷却期拦截 |
| 诊断中应用退出 | 任务终止，不写任何配置 |

---

## 9. 对现有功能的影响

- **设置页**：新增诊断入口与面板。
- **登录模块**：需要暴露分步结果与可取消能力；现有调试日志可复用，但必须默认关闭、导出前脱敏。
- **账号状态**：诊断结果不改变账号可用性，只有实际查询成功才更新。
- **隐私**：导出内容必须经过白名单字段生成，禁止直接导出原始异常堆栈中的请求细节。
