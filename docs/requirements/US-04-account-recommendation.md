# US-04 账号智能推荐与快捷复制

| 项目 | 内容 |
|---|---|
| Story ID | US-04 |
| 优先级 | P1 |
| 依赖 | US-01（告警状态用于排除风险账号） |
| 状态 | 草案 |
| 关联 | [需求池总览](README.md) · US-05 |

---

## 1. 背景与问题

多账号用户每次调用前都要在总览表格里横向比较各账号的剩余额度、可用性与重置时间，再切到账号管理页找 API Key。账号越多，这个决策成本越高。

本 Story 把「现在该用哪个账号」变成一个直接给出的建议，并支持一键复制对应 API Key，减少在多个页面之间来回切换。

---

## 2. 用户故事

> 作为持有多个账号的用户，我希望工具直接告诉我当前最适合使用哪个账号，并能一键复制它的 API Key，这样我不必自己比较多个数字再手动找 Key。

**完成条件**：总览顶部展示一个明确推荐账号及理由；用户可以一键复制该账号的 Key 并立即使用。

---

## 3. 范围

### P0

- 总览顶部「推荐账号」卡片：账号名、推荐理由、关键指标、一键复制 Key。
- 推荐算法与稳定规则。
- 无可用账号、全部查询失败等空态。
- 推荐结果随刷新更新，但避免频繁跳动。

### P1

- 展示候选账号 Top 3，可手动切换推荐。
- 按用途推荐（文本 / 图像），若平台支持按模型区分额度。
- 推荐历史与采纳记录。

### 不做

- 自动切换账号或自动改写用户配置。
- 自动调用模型。
- 代表用户创建或轮换 API Key。

---

## 4. 核心流程

```
用量查询成功
  → 过滤：查询异常、不可用、无 API Key 的账号
  → 对候选账号计算推荐分
  → 与上次推荐比较，按稳定规则决定是否切换
  → 总览顶部展示推荐卡片
  → 用户点击「复制 API Key」
  → 按需获取该账号默认/首个 Key 明文 → 写入剪贴板 → 提示成功
```

---

## 5. 功能需求

### US04-FR1 候选过滤

**规则**：

1. 排除本次查询异常的账号。
2. 排除可用性为「不可用」的账号。
3. 排除没有任何 API Key 的账号；Key 列表查询失败时，该账号不参与推荐，但需在卡片上说明「部分账号 Key 状态未知」。
4. 剩余额度无法计算（上限为 0、无数据）的账号不参与推荐。
5. 若所有账号都被排除，展示空态，不展示“最低分”账号。

### US04-FR2 推荐评分

**规则**：

1. 以通用积分池为主要依据，Flash-Lite 专属池只作为降级加分。
2. 计算输入：
   - 通用池 5h 剩余率 = 剩余 / 上限
   - 通用池 7d 剩余率
   - 可用性状态（可用 / 降级）
   - 距 5h 重置时间
3. 推荐分公式（默认，可调整）：

```
score = 5h剩余率 × 0.45
      + 7d剩余率 × 0.35
      + 可用性系数 × 0.20
```

- 可用性系数：可用 = 1；降级 = 0.3。
- 若通用池数据缺失，使用 Flash-Lite 专属池数据，并将可用性系数降为 0.1。
4. 得分保留三位小数；得分相同时依次比较：5h 剩余量高者优先 → 7d 剩余量高者优先 → 账号名升序。
5. 推荐理由文案由最高贡献项生成，例如：「5h 剩余 82%，7d 剩余 76%，额度最充裕」。
6. 推荐算法不读取历史趋势，避免冷启动时无法推荐。

### US04-FR3 推荐稳定性

**规则**：

1. 上一次推荐账号仍满足候选条件时，只有新候选得分高出 **10%** 才切换。
2. 上一次推荐账号进入告警、查询异常或不可用时，立即切换，不受 10% 限制。
3. 应用重启后不保留推荐稳定性状态，按当前数据重新推荐。
4. 推荐变化时，卡片说明「建议已切换」并给出原因，避免用户困惑。

### US04-FR4 推荐卡片展示

**字段**：

| 字段 | 说明 |
|---|---|
| 账号名 | 推荐账号 |
| 推荐理由 | 一句话说明 |
| 通用池 5h / 7d 剩余率 | 百分比与剩余量 |
| 下次重置 | 5h 窗口重置时间 |
| 状态 | 可用 / 降级 |
| 操作 | 复制 API Key、查看该账号 |

**规则**：

1. 卡片位于账号总览顶部、汇总数字下方。
2. 推荐账号存在未读告警时，卡片显示警示标记，但仍可复制 Key。
3. 降级推荐时，卡片明确标注「仅 Flash-Lite 可用」。
4. 「查看该账号」切换到账号明细并定位。

### US04-FR5 一键复制 API Key

**触发**：用户点击推荐卡片上的「复制 API Key」。

**规则**：

1. 使用该账号标记为默认的 Key；无默认 Key 时使用第一个可用 Key。
2. 仅在点击时按需获取明文，复制成功后清空界面上的临时引用。
3. 成功提示：「已复制 {账号} 的 API Key」；不展示 Key 内容。
4. 获取失败时提示原因（无 Key / 登录失效 / 平台错误），并引导到账号管理页。
5. 复制动作失效时不自动重试登录，避免触发平台风控。
6. 连续点击按现有频控处理，不做额外排队。

### US04-FR6 空态与异常

| 场景 | 展示 |
|---|---|
| 未配置账号 | 「还没有配置账号，请到账号管理页添加」+ 跳转按钮 |
| 全部账号查询失败 | 「暂无可推荐账号，请检查登录状态」+ 跳转按钮 |
| 全部账号不可用 | 「所有账号额度均已耗尽，请等待重置」+ 最近重置时间 |
| 部分账号 Key 状态未知 | 推荐卡片下方提示「N 个账号的 Key 状态未知，未参与推荐」 |
| 推荐账号在复制时变为不可用 | 提示「该账号状态已变化，建议刷新后重试」，不自动换账号复制 |

## 6. 界面与交互

```
┌─────────────────────────────────────────────────────┐
│ 推荐使用  account_03                    [可用]      │
│ 5h 剩余 82% · 7d 剩余 76% · 15:40 后重置            │
│ 额度最充裕，且 7d 窗口接近重置                       │
│                              [复制 API Key] [查看]  │
└─────────────────────────────────────────────────────┘
```

- 卡片只展示一个推荐账号，不做轮播。
- 「复制 API Key」按钮点击后 1.5 秒内显示「已复制」。
- 推荐理由文案不超过一行，超出省略并悬停显示全文。

---

## 7. 数据与状态

| 对象 | 字段 | 说明 |
|---|---|---|
| 推荐结果 | 账号、得分、理由、候选数量、是否发生切换 | 实时计算，内存态 |
| 稳定性基线 | 上次推荐账号、上次得分 | 内存态 |
| Key 状态 | 各账号是否有可用 Key | 复用现有 Key 查询与缓存 |

---

## 8. 异常与边界

| 场景 | 行为 |
|---|---|
| Key 列表查询失败 | 该账号不参与推荐，卡片提示未知数量 |
| 账号无默认 Key | 使用第一个可用 Key |
| 复制时登录失效 | 提示重新登录，不自动重试 |
| 推荐账号被删除 | 下次刷新重新推荐 |
| 得分相同 | 按 US04-FR2 的平局规则处理，保证结果稳定 |
| 推荐卡片渲染失败 | 不影响下方账号总览展示 |

---

## 9. 对现有功能的影响

- **账号总览**：新增顶部推荐卡片，需要与汇总数字、趋势区分层。
- **API Key 获取**：复用现有按需取明文能力，需确认频控不会因推荐卡片频繁刷新而误触发。
- **账号明细**：支持从推荐卡片定位账号。
- **隐私**：复制过程不展示、不记录明文；日志与告警不含 Key。
