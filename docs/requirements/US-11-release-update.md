---

## 1. 背景与问题

当前应用启动时检查一次 GitHub Release，发现新版本后可下载并替换。实际使用中存在几个问题：用户长时间不重启就收不到更新；更新提示会打断启动流程；下载只校验大小，缺少完整性校验；未签名安装包容易触发 Windows SmartScreen 拦截；托盘常驻后，更新流程还需要正确处理进程退出与重启。

本 Story 完善发布的信任链与更新体验，不改变更新来源。

---

## 2. 用户故事

> 作为长期让应用在后台运行的用户，我希望在不被打断的情况下知道有新版本，并能确认下载内容可信、更新失败可恢复，这样我不必频繁手动检查更新。

**完成条件**：应用在启动后与运行期间都能发现新版本；用户可选择稍后或跳过该版本；下载与安装过程有明确状态，失败不影响现有配置。

---

## 3. 范围

### P0

- 启动后延迟检查 + 每 24 小时检查 + 手动检查。
- 非阻塞更新提示：版本号、更新说明、稍后提醒、跳过此版本、立即更新。
- 下载进度与取消。
- 安装包完整性校验（发布方提供哈希时校验哈希；否则至少校验大小）。
- 安装前确认，说明应用将重启。
- 安装失败时保留当前版本与全部本地数据。
- 源码运行模式不执行自动更新。

### P1

- 代码签名（Windows Authenticode / macOS 签名与公证）。
- 增量更新。
- 预发布通道 / 稳定通道切换。
- 更新失败自动回滚。

### 不做

- 自建更新服务器。
- 静默强制更新。
- 跨大版本自动迁移数据（仅做兼容读取）。

---

## 4. 核心流程

```
应用启动 → 延迟 10 秒检查更新
  → 有新版 → 展示非阻塞提示
      → 稍后 → 本次运行不再提示，下次启动再提示
      → 跳过此版本 → 永久忽略该版本（可在设置中恢复）
      → 立即更新 → 下载 → 校验 → 安装确认 → 退出托盘进程 → 替换 → 重启
  → 无新版 → 静默
  → 检查失败 → 静默，不打扰用户；手动检查时提示原因
```

---

## 5. 功能需求

### US11-FR1 检查时机与频率

**规则**：

1. 启动后延迟 10 秒 `[Assumption, TBD]` 检查，避免与首次用量刷新争抢网络。
2. 应用持续运行期间每 24 小时检查一次 `[Assumption, TBD]`。
3. 设置页提供「检查更新」按钮，手动检查立即执行。
4. 手动检查进行中禁用按钮并显示状态。
5. 源码运行模式不发起更新检查，设置页显示「当前为源码运行模式，不支持自动更新」。
6. 检查请求失败（无网络、GitHub 不可达、限流）时：
   - 自动检查：静默失败，不提示。
   - 手动检查：提示失败原因，允许重试。

### US11-FR2 更新提示

**规则**：

1. 发现新版本时展示非阻塞提示（横幅或卡片），不弹出模态框遮挡操作。
2. 提示内容：当前版本 → 新版本、发布日期、更新说明摘要（最多 5 行，可展开）。
3. 操作：
   - 立即更新
   - 稍后提醒（本次运行不再提示，下次启动再提示）
   - 跳过此版本（持久化，后续不再提示该版本）
4. 用户选择「跳过此版本」后，设置页提供「恢复更新提醒」。
5. 新版本号高于被跳过的版本时，仍正常提示。
6. 更新提示不得中断正在进行的用量查询或图像生成。

### US11-FR3 下载

**规则**：

1. 下载在后台进行，显示进度（百分比或已下载 / 总大小）。
2. 支持取消；取消后删除未完成文件，不影响当前版本。
3. 下载中若用户退出应用，未完成文件可保留续传（P1）或删除（P0）；P0 选择删除并提示 `[Assumption, TBD]`。
4. 下载失败支持重试，最多自动重试 1 次，之后手动重试。
5. 下载地址必须来自发布元数据中的可信域名，使用 HTTPS。
6. 不使用系统环境代理（沿用现有安全策略）。

### US11-FR4 完整性校验

**规则**：

1. 若发布元数据提供 SHA-256，下载后必须校验；不匹配则删除文件并提示「安装包校验失败」。
2. 若未提供哈希，至少校验文件大小与发布信息一致，并提示「未能校验完整性」。
3. 校验失败不得执行安装。
4. 校验耗时超过 5 秒时显示「正在校验」。

### US11-FR5 安装与重启

**规则**：

1. 安装前二次确认：「应用将退出并重启以完成更新，当前设置与历史数据会保留。」
2. 安装前停止后台刷新与托盘常驻，避免文件占用。
3. 替换失败时：
   - 尽力恢复旧版本文件。
   - 提示用户重新下载，或提供手动安装包位置。
   - 不得删除账号配置、历史与告警记录。
4. 更新完成后自动启动新版本，并恢复到更新前的页面（与 US-10 联动）。
5. 更新后首次启动展示一次性「更新完成」提示与版本号。

### US11-FR6 版本信息与兼容

**规则**：

1. 设置页展示当前版本、构建时间、运行模式。
2. 版本比较遵循语义化版本；预发布版本默认不提示，除非用户选择预发布通道（P1）。
3. 新版本若改变本地配置结构，需兼容读取旧版本数据；升级失败不得损坏原数据。
4. 不自动降级。

## 6. 界面与交互

### 更新横幅（总览顶部，非模态）

```
新版本 v1.3.0 可用（当前 v1.2.0）
修复登录兼容性，新增用量趋势。
[查看详情] [稍后] [跳过此版本] [立即更新]
```

- 下载中替换为进度条与「取消」。
- 下载完成显示「正在校验…」→「准备安装」。
- 更新提示不使用系统通知，避免与 US-01 告警混淆。

### 设置页「关于」

```
版本        v1.2.0（构建 2026-10-21）
运行模式    安装版 / 源码运行
更新通道    稳定版
[检查更新]  [恢复更新提醒]
```

## 7. 数据与状态

| 对象 | 字段 | 说明 |
|---|---|---|
| 更新设置 | 跳过版本号、更新通道、恢复提醒状态 | 持久化 |
| 更新任务 | 版本、下载进度、状态（检查/下载/校验/安装）、失败原因 | 内存态 |
| 发布元数据 | 版本号、说明、下载地址、哈希、文件大小 | 来自 Release，不持久化 |

---

## 8. 异常与边界

| 场景 | 行为 |
|---|---|
| 无网络 | 自动检查静默失败；手动检查提示 |
| GitHub 限流 | 手动检查提示稍后重试，不自动重试 |
| 下载中断 | 删除临时文件，提示重试 |
| 哈希不匹配 | 删除文件，提示校验失败，不安装 |
| 磁盘空间不足 | 下载前检查并提示所需空间 |
| 安装时文件被占用 | 停止后台进程后重试；仍失败则提示重启系统 |
| 更新后配置不兼容 | 回退读取默认配置，保留旧数据备份 |
| 用户跳过版本后又想更新 | 设置页恢复提醒 |

---

## 9. 对现有功能的影响

- **启动流程**：更新检查延迟执行，不阻塞窗口显示。
- **托盘（US-02）**：安装前必须先退出常驻进程，更新后重新启动并恢复托盘。
- **页面状态（US-10）**：更新重启后恢复页面。
- **安全**：继续保持仅 HTTPS、可信域名、禁用环境代理；新增哈希校验。
- **发布流程**：Release 需附带哈希；签名证书未就绪前，P0 仍可交付，但不能宣称已解决 SmartScreen。
