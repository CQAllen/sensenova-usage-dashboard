# US-10 客户端状态记忆与刷新策略

| 项目 | 内容 |
|---|---|
| Story ID | US-10 |
| 优先级 | P1 |
| 依赖 | US-02（窗口隐藏、托盘状态决定“是否可见”） |
| 状态 | 草案 |
| 关联 | [需求池总览](README.md) · US-02 |

---

## 1. 背景与问题

当前应用每次启动都回到默认页面，刷新由前端定时器持续执行。窗口最小化或被遮挡时仍按原间隔请求上游，既浪费额度查询请求，也可能触发平台限流；从托盘恢复窗口时，又可能先展示旧数据再等待下一次定时刷新。

本 Story 让客户端记住用户所处位置，并让刷新节奏跟随窗口可见性与失败情况变化。

---

## 2. 用户故事

> 作为经常在几个页面之间切换的用户，我希望重新打开窗口时回到上次的位置，并且应用只在真正需要时刷新，这样既不会看到过期数据，也不会无意义地请求平台。

**完成条件**：重启后回到上次页面；窗口隐藏时停止自动请求；恢复窗口时数据足够新或立即刷新。

---

## 3. 范围

### P0

- 记住上次所在页面。
- 记住各页面滚动位置（会话内）。
- 窗口不可见时暂停自动刷新。
- 窗口恢复时按数据新鲜度决定是否立即刷新。
- 查询连续失败时退避。
- 手动刷新不受可见性与退避限制。

### P1

- 记住每个页面的筛选与展开状态（与 US-05 联动）。
- 空闲超时后降低刷新频率。
- 多显示器 / 窗口被遮挡的可见性判断。
- 刷新倒计时在托盘悬浮提示中展示。

### 不做

- 后台常驻本身（由 US-02 提供）。
- 修改用户设置的刷新间隔。
- 离线缓存历史（US-03 已提供）。

---

## 4. 核心流程

```
应用启动
  → 读取上次页面 → 校验有效性 → 打开对应页面
  → 读取刷新间隔与上次成功刷新时间
  → 窗口可见 → 启动定时刷新；数据过期则立即刷新
  → 窗口隐藏 → 暂停自动刷新（后台刷新由 US-02 接管）
  → 窗口恢复 → 判断数据新鲜度
      → 超过阈值：立即刷新一次
      → 未超过：等待下一个定时点
```

---

## 5. 功能需求

### US10-FR1 页面记忆

**规则**：

1. 记录用户最后停留的页面：账号总览、账号明细、账号管理、图像生成、系统设置。
2. 启动时恢复到该页面；页面标识非法或已移除时回到账号总览。
3. 页面切换时立即保存，不等待退出。
4. 图像生成页处于生成中时退出应用，下次启动仍进入该页，但不恢复未完成的任务，并提示「上次生成任务已中断」。
5. 首次启动默认账号总览。

### US10-FR2 滚动位置记忆

**规则**：

1. 记录每个页面的滚动位置，切换页面后返回时恢复。
2. 滚动位置仅在本次运行期间有效；重启后回到页面顶部 `[Assumption, TBD]`。
3. 数据刷新导致列表长度变化时，尽量保持当前可见账号位置；若原位置账号已不存在，回到顶部。
4. 趋势区展开状态不因刷新而重置。

### US10-FR3 可见性驱动的刷新

**规则**：

1. 窗口可见：按用户设置的间隔自动刷新。
2. 窗口不可见（最小化、隐藏到托盘、系统锁屏）：前端停止自动刷新；若 US-02 已启用后台刷新，由后台继续。
3. 窗口恢复可见：
   - 距上次成功刷新超过 60 秒 `[Assumption, TBD]`：立即刷新一次。
   - 未超过 60 秒：不额外请求，等待定时点。
4. 恢复时若已有请求在途，不重复发起。
5. 手动刷新始终允许，即使窗口刚恢复或处于失败退避期。
6. 页面切换不触发强制刷新，使用当前数据。

### US10-FR4 刷新失败退避

**规则**：

1. 连续失败 1 次：下一次自动刷新按原间隔执行。
2. 连续失败 2 次及以上：间隔按 2 倍、3 倍递增，最多 5 倍 `[Assumption, TBD]`。
3. 任意一次成功：间隔立即恢复为用户设置值，并重置失败计数。
4. 手动刷新成功后同样重置。
5. 退避期间界面显示「上次刷新失败，将在 {x} 后重试」。
6. 登录失效类错误不单独加速重试，避免触发平台风控。

### US10-FR5 数据新鲜度标识

**规则**：

1. 总览页展示「数据更新于 HH:MM」。
2. 距上次成功刷新超过 2 个刷新间隔时，标识变为「数据可能已过期」。
3. 刷新失败时展示失败提示与重试入口。
4. 窗口从托盘恢复且立即刷新期间，保留上次数据并显示加载态，不清空表格。

### US10-FR6 状态持久化边界

**规则**：

1. 持久化内容：上次页面、刷新相关失败计数（仅内存）、本机设置。
2. 不持久化：刷新中的临时数据、图像生成任务、诊断任务。
3. 持久化写入失败时不影响当前会话，下次启动回退默认。
4. 状态数据不得包含凭据与 API Key。

---

## 6. 界面与交互

- 页面切换保持现有导航结构，不新增入口。
- 恢复页面时不播放额外动画，避免闪烁。
- 数据过期时在总览标题旁显示灰色提示「数据可能已过期」，不弹窗。
- 退避提示内联展示，提供「立即刷新」按钮。

---

## 7. 数据与状态

| 对象 | 字段 | 说明 |
|---|---|---|
| 页面状态 | 上次页面、各页滚动位置、趋势区展开状态 | 上次页面持久化；滚动位置内存态 |
| 刷新状态 | 上次成功时间、连续失败次数、当前退避倍数、是否在途 | 内存态 |
| 设置 | 刷新间隔 | 沿用现有设置 |

---

## 8. 异常与边界

| 场景 | 行为 |
|---|---|
| 上次页面已不存在 | 回到账号总览 |
| 状态数据损坏 | 回退默认，不阻塞启动 |
| 应用启动时无网络 | 展示空数据与失败提示，按退避重试 |
| 窗口短暂失焦但未最小化 | 视为可见，继续刷新 `[Assumption, TBD]` |
| 系统锁屏 | 视为不可见，暂停前端刷新 |
| 托盘恢复窗口时数据仍新 | 不重复刷新 |
| 用户修改刷新间隔 | 立即按新间隔重新计时 |

---

## 9. 对现有功能的影响

- **前端定时器**：需要区分“窗口可见”和“应用后台”两种驱动，避免双触发。
- **页面导航**：记录与恢复上次页面。
- **账号总览**：新增数据时间与过期提示。
- **US-02**：窗口隐藏后的刷新由后台接管；两侧必须共享刷新状态，不能各算各的。
- **US-01**：告警评估不受前端可见性影响，后台刷新仍要评估。

## 10. 开放问题

| 编号 | 问题 | 影响 |
|---|---|---|
| Q1 | 滚动位置是否需要跨重启保留？ | 状态模型 |
| Q2 | 60 秒的新鲜度阈值是否合适？是否应随刷新间隔变化？ | 刷新体验 |
| Q3 | 窗口被其他窗口完全遮挡时，是否算不可见？ | 请求量 |
| Q4 | 退避上限 5 倍是否过高，最长可能达到 5 小时？ | 数据新鲜度 |
| Q5 | 托盘恢复时是否应总是强制刷新一次，而不是按新鲜度判断？ | 体验与请求量权衡 |
