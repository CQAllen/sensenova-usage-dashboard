---

## 1. 背景与问题

当前每次刷新只呈现「此刻」的用量。用户看到 5h 已用 60%，无法判断这是刚刚开始消耗、还是已经持续增长；看到剩余 4,000 积分，也不知道还能撑几小时。缺少历史就无法回答“还能用多久”，只能凭感觉。

本 Story 把每次查询结果留存为时间序列，提供趋势查看与耗尽预测，让总览从“读数”变成“判断依据”。

---

## 2. 用户故事

> 作为需要规划模型调用的用户，我希望看到每个账号最近一段时间的用量曲线，并知道按当前速度还能用多久，这样我可以在额度耗尽前调整调用计划或切换账号。

**完成条件**：用户能在应用内查看至少 24 小时的用量变化，并在有足够数据时看到「预计耗尽时间」或「重置前不会耗尽」的明确结论。

---

## 3. 范围

### P0

- 每次成功查询后记录用量快照。
- 历史保留 90 天。
- 新增「用量趋势」查看区：账号选择、时间范围 24 小时 / 7 天 / 30 天、5h 与 7d 曲线。
- 账号明细页展示每个积分池、每个窗口的预计耗尽时间。
- 数据不足、已耗尽、重置前不会耗尽等状态文案。
- 周期识别与曲线分段。

### P1

- 与上一周期对比。
- 多账号叠加对比。
- 按模型维度拆分（依赖平台接口）。
- 趋势图上的告警阈值参考线（与 US-01 联动）。

### 不做

- 云端同步历史。
- 预测未来用量（只做基于当前速率的线性估算）。
- 平台未提供的按模型 / 按日消费明细。

---

## 4. 核心流程

```
用量查询成功
  → 为每个账号 × 积分池 × 窗口生成快照
  → 去重（最小间隔）后写入本地历史
  → 趋势区读取历史，按时间范围聚合
  → 计算当前周期消耗速率
  → 明细页 / 趋势区展示预测结果
```

失败路径：查询失败 → 不写快照 → 趋势保留上次数据，并标注数据截止时间。

---

## 5. 功能需求

### US03-FR1 快照采集

**触发**：每次用量查询成功，且结果包含有效积分池数据。

**规则**：

1. 每个账号的每个积分池、每个窗口（5h / 7d）各记录一条快照。
2. 同一账号同一池同一窗口，与上一条快照间隔小于 60 秒时不重复写入；以最新数据覆盖同时间点 `[Assumption, TBD]`。
3. 查询失败、权限不足、无积分池数据的账号不写快照。
4. 快照至少包含：记录时间、账号标识、积分池名称与类型、窗口类型、上限、已用、剩余、重置时间。
5. 账号被删除后，历史快照保留但标记为「账号已移除」，不再出现在默认趋势选择中 `[Assumption, TBD]`。
6. 写入失败不影响查询结果的展示，只记录一次内部错误。

**结果**：历史数据可被趋势区与预测计算读取。

### US03-FR2 趋势查看

**触发**：用户在账号总览或独立的「用量趋势」区域查看。

**规则**：

1. 账号选择：默认「全部账号」，可切换为单个账号。
2. 时间范围：24 小时（默认）、7 天、30 天。
3. 指标：使用率（默认）或剩余量。
4. 同一账号下，5h 与 7d 使用不同颜色绘制两条线，并提供图例。
5. 选择「全部账号」时，仅绘制各账号的**通用积分池 5h 使用率**，避免图表过载；提示「选择单个账号可查看 7d 与专属池」。
6. 图表需标注每条线的数据截止时间。
7. 数据点过密时按时间桶聚合（取桶内最后一个值），单图最多 200 个点。
8. 鼠标悬停显示：时间、账号、池、窗口、使用率、已用/上限、剩余。

**空态**：

- 无任何历史：「暂无历史数据，保持应用运行以积累趋势。」
- 选定账号无历史：「该账号暂无足够历史数据。」

### US03-FR3 耗尽预测

**触发**：账号明细页渲染、趋势区选中单账号时。

**规则**：

1. 计算对象：单个账号 + 单个积分池 + 单个窗口 + 当前周期。
2. 有效数据要求：当前周期内至少 3 个快照，且首末快照跨度不少于 15 分钟 `[Assumption, TBD]`。
3. 消耗速率计算：
   - 取相邻快照的 `已用` 增量除以时间增量，得到每段速率。
   - 丢弃负增量（视为重置）与时间增量为 0 的段。
   - 取最近最多 12 段速率的**中位数**作为当前速率，降低突发峰值影响。
   - 单位：积分 / 小时。
4. 预测结果：

| 条件 | 展示 |
|---|---|
| 剩余量 ≤ 0 | 「已耗尽，{重置时间} 后重置」 |
| 速率 ≤ 0 | 「暂无消耗」 |
| 有效数据不足 | 「数据不足，继续观察」 |
| 预计耗尽时间早于重置时间 | 「约 {x 小时 y 分} 后耗尽（{具体时间}）」 |
| 预计耗尽时间晚于重置时间 | 「重置前不会耗尽」 |

5. 展示位置：
   - 明细页：每个池的 5h、7d 指标行下方，以次级文案展示。
   - 总览：账号行「距下次刷新」列增加悬停提示，显示通用池 5h 的预测结果（P1）。
6. 预测只使用当前周期数据；`reset_at` 变化或已用量下降时，清空上一周期数据并重新积累。

### US03-FR4 周期识别与曲线分段

**规则**：

1. 周期标识优先使用该窗口的 `reset_at`。
2. `reset_at` 变化，或本次已用量比上次下降超过 10%，视为进入新周期。
3. 新周期在曲线上断开，不连线跨周期。
4. 预测与速率计算只看当前周期。
5. 周期识别错误导致数据缺失时，退化为「数据不足」，不得给出错误预测。

### US03-FR5 历史清理

**规则**：

1. 默认保留 90 天 `[Assumption, TBD]`。
2. 每次写入快照时顺带清理超期数据。
3. 清理失败不影响查询与展示。
4. 用户可在设置页执行「清除用量历史」，需二次确认，说明不可恢复。

### US03-FR6 数据截止与失败提示

**规则**：

1. 趋势区始终显示「数据截止于 HH:MM」。
2. 最近一次查询失败时，显示「最近一次刷新失败，趋势为截至 HH:MM 的数据」。
3. 历史存储损坏时，提示「历史数据无法读取，已停止趋势展示；用量查询不受影响」，并提供清除历史入口。

## 6. 界面与交互

### 账号总览新增「用量趋势」区块（可折叠）

```
用量趋势                                   数据截止 14:32
[账号：全部 ▾]  [24 小时 | 7 天 | 30 天]  [使用率 | 剩余量]
┌──────────────────────────────────────────────┐
│   折线图：5h（蓝） / 7d（紫）                  │
│   悬停显示明细                                │
└──────────────────────────────────────────────┘
```

- 默认折叠，用户展开后加载；避免每次刷新重绘图表。
- 刷新后仅更新数据与截止时间，保持当前选择。

### 账号明细页

```
通用积分池 · 5h     ███████░░░ 68.2%
已用 6,820 / 10,000 · 剩 3,180
约 2 小时 15 分后耗尽（16:47）
```

- 预测文案为次级灰色；「重置前不会耗尽」使用正常色。
- 无预测时显示「数据不足，继续观察」。

## 7. 数据与状态

| 对象 | 字段 | 说明 |
|---|---|---|
| 用量快照 | 时间、账号标识、账号名、积分池名称、池类型、窗口类型、上限、已用、剩余、重置时间 | 本地持久化；不含凭据 |
| 周期标记 | 账号 + 池 + 窗口 + 重置时间 | 用于分段与预测 |
| 预测结果 | 速率、预计耗尽时间、状态 | 实时计算，不持久化 |

**计算口径**：使用率与剩余量沿用 [共享规则 4.1](README.md#41-积分池与窗口)。数值展示遵循 [共享规则 4.3](README.md#43-展示规范)。

## 8. 异常与边界

| 场景 | 行为 |
|---|---|
| 查询失败 | 不写快照；趋势显示上次截止时间与失败提示 |
| 上限为 0 | 不记录该窗口快照 |
| 本地时间被调整 | 丢弃时间差为负或异常的段；预测可能显示数据不足 |
| 快照重复写入 | 60 秒内去重，避免曲线抖动 |
| 历史数据量过大 | 按时间桶聚合，单图最多 200 点 |
| 用户清除历史 | 二次确认后删除；查询与告警不受影响 |
| 账号删除 | 历史保留并标记，默认趋势不展示 |

---

## 9. 对现有功能的影响

- **用量刷新**：成功回调中增加快照写入；必须有失败兜底，不能影响主流程。
- **账号明细**：新增预测文案。
- **账号总览**：新增可折叠趋势区；表格渲染不变。
- **设置页**：新增历史保留说明与「清除用量历史」。
- **导出（US-08）**：复用快照数据，导出时不得包含账号密码、JWT、API Key。
- **性能**：历史数据增长后需限制查询范围与渲染点数。
