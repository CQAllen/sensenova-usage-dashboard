# US-06 API Key 自助管理

| 项目 | 内容 |
|---|---|
| Story ID | US-06 |
| 优先级 | P1 |
| 依赖 | SenseNova 平台是否提供 Key 新建 / 禁用 / 删除接口（开发前必须验证） |
| 状态 | 草案（阻塞于平台能力确认） |
| 关联 | [需求池总览](README.md) · US-04 |

---

## 1. 背景与问题

现在用户只能查看和复制已有 API Key。新增、停用或删除 Key 都要登录 SenseNova 平台控制台，而本工具的定位正是减少登录平台的次数。如果平台提供写接口，把 Key 生命周期管理收进账号卡片，可以补上最后一段高频操作。

**前置约束**：当前已确认的是 Key 列表查询接口。写操作接口是否存在、权限与字段规则均未确认。本 Story 在确认前不进入开发。

---

## 2. 用户故事

> 作为经常为不同项目分配 Key 的用户，我希望在账号卡片里直接新建、停用或删除 API Key，这样我不必为了管理 Key 再登录一次平台。

**完成条件**：用户能在账号管理页完成 Key 新建、禁用、启用、删除，操作结果与平台一致，且明文只出现一次。

---

## 3. 范围

### P0（平台接口确认后）

- 新建 Key：填写名称，生成后仅展示一次明文。
- 禁用 / 启用已有 Key。
- 删除 Key，二次确认。
- 操作后立即刷新该账号 Key 列表与缓存。
- 平台返回的错误如实展示（脱敏）。

### P1

- 设置默认 Key。
- 修改 Key 名称。
- 操作记录（本机）。
- 按账号批量禁用 / 删除。

### 不做

- 展示或恢复已删除 Key 的明文。
- 绕过平台的配额或权限规则。
- 代替用户重置账号密码。

---

## 4. 核心流程

```
用户在账号卡片展开 Key 列表
  → 点击「新建 Key」→ 输入名称 → 确认
  → 调用平台创建
      → 成功：展示一次明文 + 复制按钮 → 关闭后不可再查看
      → 失败：提示原因，不创建本地记录
  → 列表刷新

用户点击「禁用 / 启用 / 删除」
  → 二次确认（删除必确认）
  → 调用平台
  → 成功：更新该行状态 / 移除该行，清空 Key 缓存
  → 失败：保持原状态并提示
```

---

## 5. 功能需求

### US06-FR1 能力探测与入口显隐

**规则**：

1. 应用启动或进入账号管理页时，不额外发起探测请求，避免无谓调用。
2. 若平台写接口未确认或不支持，界面不显示新建 / 禁用 / 删除入口，只保留现有查看与复制。
3. 首次调用写接口返回「不支持 / 无权限」时，隐藏对应入口并提示一次「当前平台不支持在工具内管理 Key」。
4. 能力状态按会话缓存，重启后重新判断。

### US06-FR2 新建 Key

**触发**：用户在账号卡片点击「新建 Key」。

**规则**：

1. 必填名称，长度 1–32 个字符 `[Assumption, TBD]`；去除首尾空格。
2. 同一账号内名称是否允许重复以平台规则为准；若平台拒绝，原样提示。
3. 创建成功后：
   - 若平台返回明文，弹窗展示一次，提供复制按钮，并明确提示「关闭后将无法再次查看」。
   - 用户必须点击「我已保存」或关闭弹窗后才能继续操作。
   - 明文不得写入本地配置、历史、日志。
4. 若平台不返回明文，提示「Key 已创建，请到平台查看明文」。
5. 创建后立即刷新 Key 列表与缓存；新 Key 是否默认以平台返回为准。
6. 创建失败不产生任何本地状态变化。

### US06-FR3 禁用 / 启用 Key

**规则**：

1. 仅对状态为启用或禁用的 Key 展示对应操作。
2. 禁用前二次确认，说明「禁用后使用该 Key 的调用会立即失败」。
3. 启用操作不需要二次确认。
4. 操作成功后更新该行状态，并清空该账号 Key 缓存。
5. 若该 Key 是默认 Key，禁用后是否自动切换默认以平台规则为准；界面展示平台返回结果。
6. 操作失败时保持原状态并提示原因。

### US06-FR4 删除 Key

**规则**：

1. 删除必须二次确认，确认文案包含 Key 名称与「不可恢复」。
2. 删除成功后从列表移除，并清空该账号 Key 缓存与前端明文缓存。
3. 删除默认 Key 时，额外提示「该 Key 为默认 Key」。
4. 平台拒绝删除（如仍被使用、最后一个 Key）时，如实展示原因。
5. 删除不影响用量查询与其他账号。

### US06-FR5 列表与缓存一致性

**规则**：

1. 任一写操作成功后，该账号 Key 列表必须重新拉取，不使用旧缓存。
2. 前端已显示的明文缓存需一并失效，避免展示已删除 Key 的明文。
3. 列表刷新失败时，保留操作前的显示并提示「操作已提交，但列表刷新失败，请手动刷新」。
4. 推荐账号（US-04）使用的 Key 状态变化后，下次刷新重新计算推荐。

### US06-FR6 频控与并发

**规则**：

1. 同一账号的写操作串行执行；操作进行中禁用该卡片内的其他写操作。
2. 连续写操作遵循平台限流；被限流时提示等待时间。
3. 不同账号的操作互不阻塞。
4. 页面刷新与写操作并发时，以写操作完成后的列表为准。

## 6. 界面与交互

账号卡片展开后的 Key 区域：

```
API Keys                               [+ 新建 Key]
名称         API Key              创建时间     状态     操作
default      sk-****abcd          2026-09-01   启用     [禁用] [删除]
project-a    sk-****efgh          2026-09-12   禁用     [启用] [删除]
```

- 删除按钮使用危险色，与普通操作区分。
- 新建 Key 弹窗：名称输入 + 「创建」+「取消」。
- 一次性明文弹窗：等宽字体展示，提供「复制」与「我已保存」，不提供二次打开。
- 操作结果通过 toast 提示。

---

## 7. 数据与状态

| 对象 | 字段 | 说明 |
|---|---|---|
| API Key | ID、名称、脱敏值、状态、是否默认、创建时间 | 来自平台，不本地持久化明文 |
| 一次性明文 | Key 明文 | 只在内存中短暂存在，弹窗关闭即丢弃 |
| 能力状态 | 是否支持写操作 | 会话内缓存 |

---

## 8. 异常与边界

| 场景 | 行为 |
|---|---|
| 平台无写接口 / 无权限 | 隐藏入口，提示一次 |
| 创建成功但未返回明文 | 提示到平台查看，不展示空白弹窗 |
| 用户关闭明文弹窗未复制 | 明确警告后关闭，之后只能重新创建 |
| 删除时网络中断 | 提示结果未知，要求刷新列表确认；不本地删除 |
| 最后一个 Key 被删除 | 以平台规则为准，如实提示 |
| 账号登录失效 | 引导重新登录，不自动重试写操作 |
| 写操作触发限流 | 提示等待时间，不自动重试 |

---

## 9. 对现有功能的影响

- **账号管理页**：Key 区域新增操作按钮与弹窗。
- **Key 缓存**：写操作必须使该账号缓存失效，现有主动刷新逻辑可复用。
- **隐私**：一次性明文不得进入日志、历史、导出、告警。
- **安全**：新增写请求继续使用同一账号 JWT、禁用环境代理、限制可信域名。
