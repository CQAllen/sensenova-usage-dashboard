# US-01 用量阈值告警与通知

| 项目 | 内容 |
|---|---|
| Story ID | US-01 |
| 优先级 | P0 |
| 依赖 | 无（系统通知依赖 US-02 的托盘状态展示，但可独立交付应用内告警） |
| 状态 | 草案 |
| 关联 | [需求池总览](README.md) · US-02 · US-03 |

---

## 1. 背景与问题

工具每 5 分钟刷新一次用量，但只有用户主动打开窗口才能看到结果。用户真正需要被通知的时刻——额度接近耗尽、账号登录失效、可用性从「可用」掉到「降级」——往往发生在窗口关闭时。没有告警，工具仍然要求用户“每天看一眼”，没有解决原始痛点。

本 Story 让数据主动找用户：在用量跨过风险阈值、账号登录连续失败、可用性下降时，通过应用内提示和系统通知提醒。

---

## 2. 用户故事

> 作为同时使用多个 SenseNova 账号的用户，我希望在某个账号的额度接近耗尽或登录失效时收到提醒，这样我不必每天打开工具检查，也不会在调用失败后才发现额度已经用完。

**完成条件**：用户在不打开主窗口的情况下，能收到一条可理解、可定位到具体账号的告警；同一风险不会重复打扰。

---

## 3. 范围

### P0

- 使用率阈值告警：80% / 95% / 100%。
- 账号可用性下降告警：可用 → 降级 / 不可用。
- 登录连续失败告警：同一账号连续 3 次失败。
- 告警总开关与分类开关，阈值可调整。
- 应用内提示 + 系统通知两种投递方式。
- 告警去重、周期重置、合并通知。
- 点击通知唤起主窗口并定位账号。

### P1

- 静默时段（如 22:00–08:00）。
- 告警记录页与未读计数。
- 告警恢复通知（额度重置、登录恢复）。
- 自定义每个账号的阈值。

### 不做

- 邮件、短信、企业微信 / 飞书等外部通知渠道。
- 基于历史趋势的预测型告警（由 US-03 提供数据，后续再评估）。
- 自动切换账号或自动停用账号。

---

## 4. 核心流程

```
用量查询成功
  → 逐账号逐积分池逐窗口评估
  → 跨过阈值 / 可用性下降 / 登录连续失败
  → 生成告警事件
  → 去重与合并
  → 投递：应用内 toast + 系统通知（+ 托盘状态）
  → 用户点击 → 打开主窗口并定位账号
```

失败路径：查询失败 → 不评估、不告警、不改变上一次的告警状态。

---

## 5. 功能需求

### US01-FR1 告警设置

**触发**：用户进入「系统设置 → 告警」。

**规则**：

| 设置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| 启用用量告警 | 开关 | 开 | 关闭后不再产生用量类告警 |
| 预警阈值 | 数值 | 80% | 可调范围 50%–99%，须小于严重阈值 |
| 严重阈值 | 数值 | 95% | 可调范围 51%–100%，须大于预警阈值 |
| 启用耗尽告警 | 开关 | 开 | 使用率达到 100% 时提醒 |
| 启用登录失败告警 | 开关 | 开 | 连续失败 3 次时提醒 |
| 启用系统通知 | 开关 | 开 | 关闭后只保留应用内提示 |
| 恢复默认 | 按钮 | - | 重置以上设置，需二次确认 |

**结果**：设置即时生效并持久化；下一次刷新按新阈值评估。

**异常**：阈值关系非法时不允许保存，并提示「预警阈值必须小于严重阈值」。

### US01-FR2 使用率阈值告警

**触发**：每次用量查询成功后，对每个账号的每个积分池、每个窗口（5h / 7d）评估。

**规则**：

1. 只在**跨过阈值**时产生告警：上一次评估值低于阈值，本次大于等于阈值。
2. 同一「账号 + 积分池 + 窗口 + 阈值 + 周期」只告警一次。
3. 周期由该窗口的 `reset_at` 标识；`reset_at` 变化或已用量明显下降（视为重置）时进入新周期，允许再次告警。
4. 一次评估同时跨过多个阈值时，只发送最高级别的告警（100% 优先于 95%，95% 优先于 80%）。
5. 上限为 0 或缺少用量数据时不评估。
6. 活动固定积分兜底不抑制告警：通用池耗尽即告警，即使仍可用固定积分。

**告警级别与文案**：

| 级别 | 条件 | 标题 | 正文模板 |
|---|---|---|---|
| 耗尽 | 使用率 ≥ 100% | 「{账号} 额度已耗尽」 | {池名称} {5h/7d} 已用完，{重置时间} 后恢复 |
| 严重 | 使用率 ≥ 严重阈值 | 「{账号} 额度即将耗尽」 | {池名称} {5h/7d} 已用 {使用率}%，剩余 {剩余量} |
| 预警 | 使用率 ≥ 预警阈值 | 「{账号} 用量偏高」 | {池名称} {5h/7d} 已用 {使用率}%，剩余 {剩余量} |

**结果**：生成一条告警事件；界面与通知按 US01-FR5 投递。

**异常**：同一账号在本次刷新中多个池/窗口同时触发时，按 US01-FR5 合并。

### US01-FR3 账号可用性下降告警

**触发**：账号可用性状态发生变化时。

**规则**：

1. 仅对「可用 → 降级」「可用 → 不可用」「降级 → 不可用」发送告警；状态回升不发送（P1 可增加恢复通知）。
2. 上一次状态为「查询异常」时，本次恢复正常状态不视为下降。
3. 账号首次被评估且状态为降级/不可用时，不告警，只记录基线。
4. 文案示例：「{账号} 已降级」/「{账号} 已不可用」，正文说明原因（通用池耗尽 / 专属池也耗尽）。

**结果**：生成告警事件，投递方式同 US01-FR5。

### US01-FR4 登录连续失败告警

**触发**：一次用量查询或手动登录中，账号登录失败。

**规则**：

1. 同一账号连续失败次数达到 3 次时告警；成功一次后计数清零。
2. 连续失败计数只在本次应用运行期间维护，重启后重新计数。
3. 同一账号在 1 小时内最多提醒一次 `[Assumption, TBD]`。
4. 失败原因需脱敏（不含密码、JWT、绝对路径）。
5. 「未配置密码」不属于登录失败，不告警。

**文案**：「{账号} 登录失败」；正文：「连续 3 次自动登录失败：{原因}。请到账号管理页重新登录。」

### US01-FR5 通知投递与合并

**投递渠道**：

1. **应用内提示**：窗口可见时，在右下角显示 toast，按级别配色，8 秒后自动消失，可手动关闭。
2. **系统通知**：窗口不可见（最小化 / 托盘 / 被其他窗口遮挡）时发送系统通知。
3. **托盘状态**：由 US-02 根据未处理告警改变图标颜色；系统通知不可用时作为兜底。

**合并规则**：

1. 同一次刷新产生的多条告警合并为**最多一条**系统通知。
2. 合并通知标题按最高级别：「{N} 个账号需要关注」。
3. 正文最多列出 3 个账号及原因，其余用「等 N 个账号」概括。
4. 应用内 toast 同样合并，不逐条刷屏。

**点击行为**：点击系统通知 → 唤起主窗口 → 切换到「账号明细」→ 滚动并高亮对应账号（多账号时定位第一个）。

**异常**：系统通知发送失败时静默降级为应用内提示 + 托盘状态，不重试、不阻塞查询。

### US01-FR6 告警去重与状态

**去重键**：`账号 + 积分池 + 窗口 + 阈值 + reset_at`。

**状态规则**：

1. 告警事件生成后进入「未读」；用户打开对应账号或点击通知后标记「已读」。
2. 同一去重键在周期内不重复生成事件，即使使用率在阈值上下波动。
3. 周期重置时清除该键的历史状态。
4. 用户修改阈值后，按新阈值重新建立基线，不补发历史告警。

### US01-FR7 告警记录（P1）

- 设置页或独立「告警」入口展示最近告警：时间、账号、类型、级别、内容、已读状态。
- 支持标记全部已读；记录保留 30 天 `[Assumption, TBD]`。
- 空态：「暂无告警记录」。

## 6. 界面与交互

### 设置页新增「告警」卡片

```
告警
  启用用量告警        [开]
  预警阈值            [80 %]
  严重阈值            [95 %]
  启用耗尽告警        [开]
  启用登录失败告警    [开]
  启用系统通知        [开]
  [恢复默认]
```

- 阈值修改后即时保存，或与「保存」按钮一致；与现有设置页交互保持一致。
- 阈值非法时就地提示，不弹窗。

### 应用内 toast

- 预警：黄色；严重：橙色；耗尽/登录失败：红色。
- 内容一行标题 + 一行说明，可点击定位账号。

### 账号总览

- 账号行在存在未读告警时显示告警角标（数字或圆点）。
- 进入账号管理 / 明细后角标清除。

## 7. 数据与状态

| 对象 | 字段 | 说明 |
|---|---|---|
| 告警设置 | 各开关、预警阈值、严重阈值 | 与现有设置一起持久化 |
| 告警事件 | 事件 ID、时间、类型、级别、账号、积分池、窗口、阈值、当前值、周期标识、已读 | 仅存本机，不含凭据 |
| 评估基线 | 上次使用率、上次可用性、连续登录失败次数 | 内存态，重启后重建 |

**计算口径**：使用率沿用 [共享规则 4.1](README.md#41-积分池与窗口)；可用性沿用 [共享规则 4.2](README.md#42-账号可用性沿用现有定义)。

---

## 8. 异常与边界

| 场景 | 行为 |
|---|---|
| 查询失败 | 不评估、不告警、不改变基线 |
| 无积分池数据 | 不产生用量告警 |
| 应用刚启动 | 首次评估只建立基线，除登录失败外不补发历史告警 |
| 系统时间被调整 | 周期判断以 `reset_at` 变化和用量下降为准，不依赖本地时间差 |
| 多个账号同时告警 | 合并为一条通知，避免刷屏 |
| 系统通知权限被拒 | 应用内提示 + 托盘状态兜底，设置页提示一次 |
| 用户关闭全部告警 | 不生成任何告警，也不改变托盘状态 |

---

## 9. 对现有功能的影响

- **设置页**：新增告警设置卡片；保存设置时需要兼容旧配置缺失字段。
- **用量刷新**：查询成功后增加评估步骤；评估失败不得影响查询结果展示。
- **账号总览 / 明细**：新增告警角标与定位高亮。
- **托盘（US-02）**：告警状态作为托盘图标颜色的输入。
- **隐私**：通知文案不得包含完整 API Key、JWT、密码。
